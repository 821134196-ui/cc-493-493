# 消防通道临停占道管理系统

物业记录消防通道上的临停占道车辆并完成全流程处置:**上报发现(车牌/区域/时间/现场照片)
→ 保安接单巡查 → 短信/电话联系(模拟)→ 值班负责人决定是否升级拖移 → 车辆驶离 →
另一名保安复核通道恢复 → 结案封闭**。住户可查看与自己车辆有关的通知。

仅依赖 **Python 3 标准库**,无需安装任何包;SQLite 存事件数据,本地目录存照片,
短信网关与车牌识别均为**可控模拟**。

## 一条命令启动

```bash
./run.sh
```

然后浏览器打开 <http://127.0.0.1:8000>(可用 `PORT=8080 ./run.sh` 改端口,
`RESEED=1 ./run.sh` 重置演示数据)。等价于 `python3 -m app`。

## 页面

- **通道平面图**:以各楼栋消防出入口(🚪 蓝色锚点)为视觉中心;**红色仅用于正在阻断
  消防通道的出入口/车道**并带脉冲;待复核为琥珀色;历史事件保持中性色。跨楼栋保安只见
  红色阻断提示、不见车牌等详情。点击锚点可上报或进入事件。
- **事件处置**:事件卡片展示车牌、状态、**占用时长**、发现时间与**实际处置人**;
  手机端右下角有醒目的红色 **📷 拍照上报** 浮动按钮(`capture="environment"` 直接调起相机)。
- **事件详情**:现场/驶离/复核照片、**联系记录**、**事件时间线**(每一步留痕),
  以及按角色出现的处置按钮。
- **清障复核**:车辆驶离登记后,必须由**另一名保安/值班负责人**现场确认通道恢复才能结案;
  驶离登记人本人的复核按钮被禁用。
- **我的通知**:住户只收到登记在自己名下车辆的占道/联系/升级/结案通知。
- **统计**:事件总量、处置中、待复核、平均/中位占用时长、联系失败率、重复合并次数、
  识别更正次数,每日事件与按楼栋分布(单蓝色系,红色不参与图表)。
- **模拟控制**(仅值班负责人):一键让车牌识别器认错一位、让短信网关整体故障或指定
  号码投递失败——失败均写入联系记录与短信发件箱。

## 业务规则与留痕

| 场景 | 行为 |
|---|---|
| 同一车辆占用期间重复上报 | 数据库部分唯一索引 + `BEGIN IMMEDIATE` 保证**合并到原单**,计数 +1 并写时间线,绝不重复开单 |
| 车辆驶离后二次驶入 | 前序已结案,允许生成新单(seed 中 京A12345 即二次占道) |
| 联系失败 | 无登记号码 / 网关故障 / 指定号码失败均落 `contact_logs(result=failed)` 与 `sms_outbox` |
| 车牌识别错误 | 可更正车牌,原识别值保留(`original_plate`),更正动作与原因入时间线 |
| 紧急救援占道 | 上报时勾选,单独标记;仅这类事件可登记"救援结束放行" |
| 升级拖移 | 保安只能申请;**值班负责人**必须显式勾选确认才能批准;未经批准不能登记拖离 |
| 拖移取消 | 仅值班负责人,必须填原因,留痕后事件回到巡查中 |
| 复核人分离 | 驶离登记人不能复核自己的单;服务端按 `departed_by <> 当前用户` 条件更新 |
| 并发结案 | `UPDATE ... WHERE status='departed'` 的影响行数判定唯一赢家,另一提交得到 409 |
| 封闭事件 | `closed` 状态对任何人不可写;住户只有只读权限 |
| 跨楼栋可见范围 | 保安仅本栋详情/操作;他栋仅地图红色阻断提示;住户仅本人车辆 |

## 数据与目录

```
data/firelane.db      SQLite 数据库(事件、时间线、联系、照片元数据、会话、模拟开关)
data/photos/          现场/驶离/复核照片(按魔数校验 JPEG/PNG/GIF,单文件 ≤8MB)
app/                  后端(stdlib http.server + sqlite3)
static/               前端(原生 HTML/CSS/JS,无构建)
tests/test_app.py     端到端测试(起真实 HTTP 服务,临时库)
```

## 测试


复核人分离、**并发结案唯一赢家**、升级须负责人显式确认、拖移取消/识别更正/
联系失败/紧急救援留痕、拖离须先升级、统计与模拟开关权限(共 16 组)。
